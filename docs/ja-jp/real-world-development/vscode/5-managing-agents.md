GitHub Copilot を agent mode で使うと、コードベースを調べ、変更を提案し、ファイルを編集して、コマンドを実行します。この作業はマシン上でリアルタイムに進むため、VS Code の Copilot Chat ではツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、変更ごとに採用または取り消しを選び、エディターを離れずに追加プロンプトで会話を調整できます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- セッション中にエージェントへ指示し、ハイコントラストに加えてライトモードを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントが、ハイコントラストモードを実装しています。作業中、デザインチームから新たな依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加します。新しい会話を始めずに、既存のセッションを続けます。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集などの各ステップが表示されます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツール呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインライン表示されます。
   - **Keep** を選択して変更を採用します。
   - **Undo** を選択して変更を元に戻し、再度作業するようエージェントに依頼します。
4. チャット上部の **Files changed** を開き、セッション中に変更されたファイル全体を確認することもできます。

> [!NOTE]
> ターミナルコマンドの実行など、ツールの使用許可を求められた場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードを実装し終えるまで待ちます。最後に変更の概要が表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードができたら、同じ会話でライトモードの切り替えを追加します。同じチャットセッションを続けることで、エージェントは以前に変更したコンポーネント、スタイルの方針、local storage の使い方を引き継ぎます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントはすでに行った変更を確認し、ライトモードの追加を提案します。
3. 新しい編集を確認し、差分ごとに **Keep** または **Undo** を選びます。
4. エージェントの方針が希望と異なる場合 (例: 切り替え UI を意図しない方法でリファクタリングする場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、補足プロンプトを送ります。

> [!TIP]
> 進行中のセッションを調整すると、最初からやり直すより効率的です。追加のプロンプトを使って変更を依頼します (例: 「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使用する」)、方向を修正します (例: 「3つ目の切り替えを追加せず、既存の設定パネルにライトモードを組み込む」)、または範囲を広げます (例: 「両方の切り替えにキーボードショートカットも追加する」)。

## 作業内容をレビューする

コミットする前に、エージェントが変更したすべての内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更したファイルをいくつか開き、差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持など、アクセシビリティパターンが反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat agent mode を使い、進行中のセッションを監視して調整しました。ファイル編集を確認しながら採用または拒否し、コンテキストを保ったまま追加プロンプトを送信しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を採用または拒否しました。
- セッション中に追加プロンプトを送り、エージェントを調整しました。

次は、アクセシビリティの変更をプルリクエストとして公開し、このラボを通じてローカルのカスタムエージェントが作成した変更をレビューします。
